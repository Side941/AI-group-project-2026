AI Group Project 2026 — Structure & Processes

Depression / suicide-risk RAG pipeline over ICD-11 clinical criteria · branch rami-experiment · surveyed Jul 31, 2026 (updated 08:00)

The project is a retrieval-augmented classification pipeline: it labels social-media posts as suicidal, depression, or normal, grounding each decision in ICD-11 CDDR clinical criteria retrieved from a local knowledge base and classified by Qwen3 models running locally through Ollama. The research question is whether retrieval improves factuality (groundedness in clinical evidence), not just accuracy.

3. Build processes

3.1 Knowledge-base build — python src/builders/run_kb_pipeline.py

StepWhat happensKey constants
Extractpdftotext pulls the CDDR clinical content page rangepages 109–694
ChunkSplit per disorder code and section, cap length with overlap≤220 words, 35 overlap
Validate + writeJunk/appendix filters, section normalisation, JSON out1,569 chunks
Embed + ingestBioLORD-2023 embeddings into ChromaDB (cosine HNSW)batch 64, max_seq 512

Flags: --skip-chunking, --rebuild, plus path/model overrides.

3.2 Multiclass dataset build — python src/builders/build_multiclass_dataset.py

  1. Load the Hugging Face corpus (ourafla/Mental-Health_Text-Classification_Dataset, 50,604 posts; local cache first, Hub fallback). The Hub repo renamed its files upstream; the download maps to the new names via HF_HUB_TRAIN_FILE / HF_HUB_TEST_FILE in config.py, and regenerated CSVs hash identically to the committed ones.
  2. Clean: drop anxiety, strip URLs/whitespace, keep 40–2,000 chars, dedupe → suicidal 10,753 · depression 14,178 · normal 12,073.
  3. Stratified eval sample: 150/class, seed 42 → multiclass_eval.csv (450 rows).
  4. Dev slice carved from eval: 10/class, seed 43 → multiclass_dev.csv (30 rows).
  5. Each CSV ships with a meta JSON recording source, seed, counts, and SHA256.

3.3 Few-shot store build — python src/builders/rebuild_all_artifacts.py

  1. Hold out all 450 eval texts from the sampling pool (36,554 posts remain).
  2. Sample 200 examples per label, seed 1337 → 600 examples.
  3. Embed with BioLORD-2023 → ChromaDB collection fewshot_multiclass under knowledge_base/fewshot/.
  4. Write datasets/processed/fewshot_db.meta.json as provenance.

Flags: --skip-evals, --reuse-fewshot-db, --seed.

4. Retrieval

Retrieval poolAll retrievers search the same filtered pool: chunks whose disorder code starts with 6A6/6A7/6A8 (mood disorders) and whose section is Essential Features or Boundary with Normality — 137 of the 1,569 chunks.
RetrieverHow it works
BM25 (sparse)rank_bm25 BM25Okapi over NLTK-tokenized chunk text (Porter stemming, stopwords removed), plus a 0.75× bonus for query-token overlap with the disorder name. No model, no startup cost.
Dense (BioLORD)Queries encoded with FremyCompany/BioLORD-2023, matched in ChromaDB by cosine similarity (score = 1 − distance). One query per section, merged by max score.
Hybrid (weighted RRF)Fuses the two rank lists: score = α/(60 + BM25 rank) + (1 − α)/(60 + dense rank), α = 0.3. Fusion on flat ranks; expansion applied afterwards.

Section expansion (all three): after scoring, over-fetch k×4, keep the top-k distinct disorders, and inject each disorder's sibling section (Essential Features ↔ Boundary with Normality) just below the original hit (score × 0.999) — so the LLM always sees both the criteria and the normality boundary. Flat mode skips this.

The few-shot retrievers mirror the same trio over the 600 labeled example posts.

5. Experiments & results

Winning configuration (phase 8, final 450-post eval)Dense retrieval + mood-code filter, k = 5, zero-shot prompt, section expansion on, Qwen3 1.7B, thinking off — 68.67% accuracy with per-class precision/recall/F1 and a confusion matrix recorded.

The experiment grid in notebooks/analysis.ipynb changes one dimension per phase against a fixed baseline (Qwen3 1.7B, k = 5, zero-shot, expand) on the 30-post dev slice; only phase 8 runs the full eval.

Every run records predicted/true label, refusal and empty-output flags, token-cap hits, timing, thinking traces, and the retrieved chunks; CSVs land in results/.

Dynamic few-shot experiment (experiments/exp_fewshot_rag.py): retrieves labeled example posts from the few-shot store (BM25/dense/hybrid), optionally adds ICD-11 chunks, and calls Ollama. --dry-run inspects the prompt without a model; --compare pits zero-shot vs few-shot vs few-shot+KB. Defaults: 3 examples, 3 KB chunks, α = 0.3, qwen3:0.6b.

Supporting analyses (analysis/): retriever_comparison.py (suicid* hit rate, MRR, latency, memory, BM25–dense overlap) · bm25_suicide_keywords.py (suicidal posts share rare, high-IDF terms with ICD-11 criteria) · page_boundary_experiment.py (pages beyond 694 add mislabeled chunks, not usable signal).
